# Pharm Medication Revamp Plan

## Goal

Replace the current flat, partially auto-filled pharm catalog with a class-first medication reference that uses a curated medication schema modeled on the requested format:

- top-level therapeutic class
- subclass
- medication name
- structured clinical fields per medication
- external reference links to RxNav, RxNorm, and RxMix

The immediate product direction is:

1. stop presenting low-trust fallback clinical text as if it were curated content
2. make every medication render from the same structured schema
3. keep RxNav/RxNorm/RxMix links available for every medication during the transition
4. preserve one-click VS Code task workflows for rebuilds and audits

## Current State Snapshot

As of `2026-08-18`, the pharm module has three important constraints:

1. The active runtime dataset is a flat `medications` array generated by [pharm/scripts/build_rxclass_medication_catalog.py](/Users/claytongoddard/Git dub/Ref-pages_v3/pharm/scripts/build_rxclass_medication_catalog.py), not a nested class-first source of truth.
2. The current build is scoped to a general-surgery subset. The latest build report shows `2233` merged candidates narrowed to `238` final records in [pharm/assests/rxclass_catalog_report.json](/Users/claytongoddard/Git dub/Ref-pages_v3/pharm/assests/rxclass_catalog_report.json).
3. The detail panel in [pharm/pharm_app.js](/Users/claytongoddard/Git dub/Ref-pages_v3/pharm/pharm_app.js) still renders sections like `MOA`, `Indications`, `Contraindications`, and `Adverse Effects`, then appends a live RxNorm section afterward.

Quality issues are structural, not cosmetic:

- The generator is RxClass-first, with optional openFDA enrichment.
- The build still relies on fallback text for missing fields.
- The page hides some placeholders at render time instead of solving the source-data problem.
- The current canonical data shape is optimized for search cards, not for clinically complete medication monographs.

## Product Decision

The revamp should split the system into two layers:

1. `Canonical curated medication content`
   This is the human-maintained source of truth and should match the class/subclass/medication structure you want.
2. `Derived runtime index`
   This is a compiled flat search index generated from the canonical source for fast filtering, searching, and rendering.

That avoids forcing the app UI to search directly through a deeply nested JSON tree while still making the content source readable and editable.

## Target Canonical Schema

Use a canonical schema that follows your requested layout, with one small extension: every medication gets a `References` block and a `Curation-Status` field.

```json
{
  "Anticoagulants": {
    "Vitamin K Antagonists": {
      "Warfarin": {
        "Brand-name": ["Coumadin", "Jantoven"],
        "Mechanism": "Inhibits vitamin K epoxide reductase (VKORC1), decreasing synthesis of functional factors II, VII, IX, X and proteins C and S.",
        "Indications": ["Atrial fibrillation", "DVT", "PE", "Mechanical heart valves", "VTE prevention"],
        "Contraindications": ["Pregnancy", "Active major bleeding", "Severe uncontrolled bleeding risk"],
        "Adverse-Effects": ["Bleeding", "Skin necrosis", "Purple toe syndrome", "Teratogenicity"],
        "Monitoring": ["PT/INR"],
        "Reversal": ["Vitamin K", "4-factor PCC", "Fresh frozen plasma"],
        "References": {
          "RxNav": "https://mor.nlm.nih.gov/RxNav/search?searchBy=RXCUI&searchTerm=11289",
          "RxNorm-API": "https://rxnav.nlm.nih.gov/REST/rxcui/11289/allrelated.json",
          "RxMix": "https://mor.nlm.nih.gov/RxMix/"
        },
        "Curation-Status": "curated"
      }
    }
  }
}
```

### Required Medication Fields

Every medication record should support these fields:

- `Brand-name`
- `Mechanism`
- `Indications`
- `Contraindications`
- `Adverse-Effects`
- `Monitoring`
- `References`
- `Curation-Status`

### Optional Medication Fields

Add these only when clinically useful:

- `Reversal`
- `Notes`
- `Status`
- `Dosing`
- `Pregnancy`
- `Renal`
- `Hepatic`
- `Black-Box-Warnings`

### Allowed Status Values

Use a short controlled vocabulary:

- `curated`
- `link-only`
- `needs-review`
- `deprecated`

`link-only` is the key transition state for records that have class placement and external references but do not yet have curated clinical content.

## Derived Runtime Schema

Do not force the page to consume the canonical nested JSON directly. Compile it into a runtime search index like:

```json
{
  "version": "2",
  "generatedAt": "2026-08-18T00:00:00Z",
  "medications": [
    {
      "id": "warfarin",
      "name": "Warfarin",
      "topLevelClass": "Anticoagulants",
      "subclassPath": ["Vitamin K Antagonists"],
      "displayClass": "Vitamin K Antagonists",
      "Brand-name": ["Coumadin", "Jantoven"],
      "Mechanism": "...",
      "Indications": ["..."],
      "Contraindications": ["..."],
      "Adverse-Effects": ["..."],
      "Monitoring": ["PT/INR"],
      "Reversal": ["Vitamin K", "4-factor PCC", "Fresh frozen plasma"],
      "References": {
        "RxNav": "...",
        "RxNorm-API": "...",
        "RxMix": "..."
      },
      "Curation-Status": "curated"
    }
  ]
}
```

The page can keep fast search/filter behavior while the authored data stays class-first.

## Reference Link Strategy

Every medication should have external reference links, even when the clinical fields are incomplete.

### Minimum external references per medication

- `RxNav`
- `RxNorm-API`
- `RxMix`

### Implementation rules

- If an `RxCUI` exists, build the links from `RxCUI`.
- If no `RxCUI` exists yet, build a search-based RxNav link from the medication name and mark the record `needs-review`.
- Keep these links static in the compiled dataset instead of depending on a live lookup just to render the detail panel.

### Official source notes

- RxNav and RxMix are official NLM tools.
- RxNav is updated monthly following RxNorm releases.
- RxMix is intended for interactive or batch workflows over RxNorm, RxTerms, and RxClass APIs.

## Architecture Changes

### 1. New canonical content location

Add a new source tree such as:

```text
pharm/content/medications/
  medication_reference.json
```

If the file gets too large, split it by top-level class:

```text
pharm/content/medications/
  hematology.json
  cardiovascular.json
  anti_infectives.json
  endocrine.json
```

This is better for review and merge conflict control than keeping one giant generated file in `pharm/assests/`.

### 2. Replace generator ownership

The current generator should stop being the primary owner of clinical text.

New ownership model:

- RxClass and RxNorm: classification and identifiers
- openFDA or other machine sources: candidate enrichment only
- curated JSON: final displayed medication content

Machine-generated text should populate draft fields, never silently publish as final clinical content.

### 3. Compile instead of directly generating display content

Add a compiler step that:

1. validates the canonical schema
2. enriches records with identifiers and links
3. emits a flat runtime dataset
4. emits class-tree assets for the UI
5. emits a curation audit report

### 4. Simplify the front end

The page should stop mixing curated sections with runtime RxNorm fetching as a primary content source.

Target UI behavior:

- primary detail panel content comes from the compiled dataset
- external links are always visible
- live RxNorm fetch becomes optional enhancement, not required content
- `link-only` records display a clear banner such as: `External reference only; curated summary pending.`

## Migration Plan

### Phase 0: Freeze misleading fallbacks

Objective:
Stop treating machine fallback text as acceptable clinical content.

Work:

- treat fallback-generated sections as missing, not as content
- add a visible `link-only` or `needs-review` state in the UI
- keep external links available for all medications

Exit criteria:

- no medication appears clinically complete unless its fields are actually curated

### Phase 1: Introduce the canonical schema

Objective:
Create the new source-of-truth format without breaking the current page.

Work:

- create `pharm/content/medications/`
- define the JSON schema for class -> subclass -> medication
- add schema validation
- compile canonical content into a new runtime dataset

Exit criteria:

- new curated schema exists
- build produces a valid flat runtime index from it

### Phase 2: Seed all medications as link-only

Objective:
Ensure broad coverage quickly, even before clinical curation is complete.

Work:

- migrate the current 238 active medications first
- create one record per medication in the new class-first structure
- populate:
  - class placement
  - medication name
  - aliases/brand names if reliable
  - RxCUI
  - RxNav/RxNorm/RxMix links
  - `Curation-Status`
- set incomplete medications to `link-only`

Exit criteria:

- every currently shipped medication exists in the new schema
- every one has external reference links

### Phase 3: Curate class packs

Objective:
Replace link-only records with real medication content in controlled batches.

Recommended first packs:

1. `Anticoagulants`
2. `Antiplatelets`
3. `Common perioperative antibiotics`
4. `Sedatives / analgesics / vasopressors`
5. `Insulins and endocrine essentials`

Work:

- author class pack JSONs in the exact target structure
- require manual review before status changes from `link-only` to `curated`
- generate audit reports for missing fields and inconsistent naming

Exit criteria:

- first high-yield classes are fully curated
- no fallback language remains in those classes

### Phase 4: Switch the UI to the new model

Objective:
Retire the old field assumptions in the front end.

Work:

- update [pharm/pharm_app.js](/Users/claytongoddard/Git dub/Ref-pages_v3/pharm/pharm_app.js) to read the compiled dataset from the new canonical schema
- update labels to match the new field names
- add `Curation-Status` banner logic
- add explicit external reference buttons
- keep search, route filters, and class filters working

Exit criteria:

- pharm page renders only from the new compiled dataset
- legacy flat generator is no longer the displayed content source

### Phase 5: Expand beyond the general-surgery subset

Objective:
Decide whether the reference remains a curated focused formulary or grows into a broader medication library.

Decision point:

- If the goal is a high-trust perioperative formulary, keep the smaller scope and maximize quality.
- If the goal is a broad pharm reference, expand only after the curation pipeline is proven.

Recommended decision:

- keep the active UI scoped until the new content model is stable
- do not re-expand to thousands of low-curation records during the migration

## New Scripts

All runnable scripts should keep a `USER SETTINGS` block and be runnable through VS Code tasks.

Recommended replacements:

1. `pharm/scripts/build_medication_reference_catalog.py`
   Compiles canonical class-first content into the runtime flat index and generated assets.
2. `pharm/scripts/seed_medication_reference_links.py`
   Builds initial `link-only` medication records from the current dataset and known RxCUIs.
3. `pharm/scripts/validate_medication_reference_schema.py`
   Validates required fields, duplicate medication names, duplicate RxCUIs, and class nesting.
4. `pharm/scripts/audit_medication_reference_content.py`
   Reports missing fields, status counts, and classes not yet curated.

5. run pharm smoke tests

## Acceptance Criteria

The revamp is complete when all of the following are true:

1. The authored medication source is class-first and matches the requested schema shape.
2. Every shipped medication has RxNav, RxNorm, and RxMix links.
3. The detail panel no longer depends on fallback clinical text.
4. `link-only` records are clearly labeled.
5. The front end reads only compiled output from the new canonical source.
6. Rebuilds and audits are available as VS Code tasks.
7. Smoke tests confirm that search, filtering, and detail rendering still work.

## Recommended First Implementation Slice

Do not try to rewrite every class at once.

Build this first slice:

1. introduce the canonical schema and compiler
2. migrate `Anticoagulants`
3. migrate `Antiplatelets`
4. mark all remaining medications as `link-only`
5. update the UI to display status plus external reference buttons

That gets the new architecture live quickly while keeping the highest-yield content at the quality bar you want.
